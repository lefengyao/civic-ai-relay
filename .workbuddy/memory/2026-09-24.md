## 新增「客户端接入信息」（v0.3.4）

**需求**：让其他软件（OpenAI 兼容客户端）接进来，先用 token 鉴权、不做用户体系，
每个客户端绑一个分组，且不能让客户端拿到上游 API Key。

**结论**：现有 `/v1` 接口已经具备全部能力（crk_ 客户端 Key、分组隔离、上游 Key
AES-256-GCM 加密），真正缺的是「客户端该填什么」这一环 —— 明文密钥只在创建/重置时
返回一次，Base URL 与模型名分散在配置页和模型页，运维自己拼极易拼错。遂补齐此处。

**改动**
- `internal/store/keys.go`：把「客户端能用哪些模型」的 SQL 抽成 `authorizedModelsSelect`
  + `queryAuthorizedModels`（原来只有按 token 查的一处）；新增 `AuthorizedModelsForKey`。
  刻意不校验 `k.enabled`：停用的 Key 也要能预览模型，否则运维没法判断 401 的成因。
- `internal/httpapi/admin.go`：新增 `GET /admin/api/keys/{id}/connection`（在 `keyItem` 内分发，
  与 `groups`/`rotate` 同级）+ `clientBaseURL`（尊重 `X-Forwarded-Proto`）。
- `web/admin.html`：Key 行加「接入信息」按钮与弹窗（Base URL、脱敏密钥标识、模型清单、
  问题清单、可直接复制的自检 curl），回环地址会额外提示「其他设备请换局域网 IP」。
- 文档：新增 `docs/client-integration.md`；`README.md`、`docs/admin-api.md` 补说明。
- 测试：`store/keys_test.go::TestAuthorizedModelsForKeyMatchesTokenLookup`、
  `httpapi/admin_test.go::TestAdminKeyConnectionTellsClientsWhatToFill`。

## 最小网页 demo（同日下午）

**需求**：写一个最小网页对接容器，验证「能否使用」。

**关键发现：relay 的公共接口不带 CORS 头**（`OPTIONS /v1/models` → **405**，无 `Access-Control-*`）。
所以网页从别的源（`file://` 或另一个端口）直连 `/v1` 必被浏览器拦掉，控制台报 CORS 错、
请求看起来根本没发出去。**结论：网页类客户端必须走同源反向代理**（生产同理），或以后给服务端加 CORS。

**交付**
- `_e2e/relay-demo.html`：单文件、零依赖的原生 JS 页面（模型下拉 / 流式开关 / 错误码直显 / 用量耗时）。
- `_e2e/relay_demo_server.py`：同源服务 —— 出页面 + 把 `/v1/*` 反代到 `127.0.0.1:8000`；
  启动时幂等准备一个专用 Key「网页测试」（绑第一个启用分组），明文缓存在 `_e2e/demo-key.txt`（gitignore），
  **不动已有的 Free Key**。HTTP/1.0 + 连接关闭表示结束 + `read1()` 逐块转发，SSE 才能实时到浏览器。
- `docs/client-integration.md` 补「网页/浏览器类客户端：先解决跨域」一节。

**实测**（走 8088 代理，等同浏览器视角）：页面 200、`/__config` 200、拉模型 200 得到 `mimo/mimo-v2.5`、
非流式对话 200（真实上游返回「收到」）、流式 200 含 `[DONE]` 共 65 帧、错密钥 401 `invalid_api_key`、
错模型名 400 `model_not_allowed`、未实现端点 404 `not_found`。

**踩坑**：自己写的测试脚本 `call(method, path, body, headers)` 把 headers 传成了第 3 个位置参数（=body），
结果 `Authorization` 根本没发出去，误判成「`/v1/models` 401 是系统 bug」——定位前先怀疑自己的探针。

## 短时令牌（v0.3.5，用户澄清后的真实需求）

**用户的真实意图**（我先前理解偏了）：后端的意义是**不对外暴露上游 key + 客户端用「短时令牌」接入**，
泄露/滥用都有兜底。原来的 `crk_` Key 是**永久有效**的，缺的正是「会自己过期」这一环。

**实现**
- 迁移 **v11**：`client_keys.expires_at_utc`（NULL = 永久 → 历史 Key 升级后性质不变）。
- `store/keys.go`：`ClientKey.ExpiresAt` + `Expired(now)` + `ErrClientKeyExpired`；
  `AuthenticateClientKey` 过期即返回该错误（连同 Key 记录）；`nullableTime` 把坏掉的时间按永久处理
  （坏时间不该把 Key 变成永远不可用）；`UpdateClientKey` 用 `ExpiresAt` / `ClearExpiresAt` 两字段保三态。
- `relay.ErrTokenExpired` → `public.go` 映射 **401 `token_expired`**（与 `invalid_api_key` 分开，
  客户端才知道是「该换令牌」而不是「凭据不对」，不会当服务故障反复重试）。`Models` 与 `Begin` 两条路径都改了。
- 管理端：`ttl_seconds` 三态（缺省=不动 / 0=永久 / >0=从现在起重新计时即续期）；
  `keysList` 与 `connection` 返回 `Expired`/`ExpiresAtUTC`/`ExpiresInSecs`；connection 的 issues 会点明
  「客户端会收到 401 token_expired」，剩余 < 24h 进 warnings。
- 管理台：创建表单加「令牌有效期（小时）」；编辑弹窗加同名字段（**留空=不动**，placeholder 显示当前到期时间）；
  列表状态列显示「令牌永久有效 / X 天后过期（<24h 标黄）/ 令牌已过期（红）」；接入信息加「有效期」行。

**实测（真实实例 8000，升级到 v0.3.5 后）**
升级后老 Key（`Free`、`网页测试`）都仍是「永久」且可正常调用 → 迁移不影响历史数据。
新建 30 分钟令牌 → 接入信息给出 `2026-09-24T05:52:03Z / 剩 1799 秒` → 可用 200 →
改成 1 秒 → 到期后 `/v1/models` 与对话都 **401 `token_expired`** → 接入信息 `ready=false` 且点明原因 →
续期后立即 200 → **改名不影响有效期** → 删除演示 Key。

**回归**：`go test ./...` 全绿（新增 3 个测试：store 的过期语义、public 的 token_expired、admin 的 TTL 三态）；
`_e2e/run_client_onboarding.py` 加了「短时令牌」整段断言。镜像 `civic-relay:v0.3.5` 已构建并在本机实例运行。

## 应用型凭据（v0.3.6，用户进一步澄清）

**用户澄清**：客户端**不能保存网关的 key** —— 软件连网关「不需要 key」，只指定一个分组
（未来可选分组）；目的是**防止用户把 key 拿到应用外去用**。
→ 方向与短时令牌不同：那个是「有密钥但会过期」，这个是「压根没有密钥」。

**实现（迁移 v12：`client_keys.public_id`）**
- `Keyless: true` 创建记录：生成公开的应用标识 `app_<22 位>`，**密钥明文彻底丢弃**
  （不返回、不落盘、不打日志）；`token_digest` 是无人知晓的随机摘要。
- 认证走请求头 `X-App-Id`。`AuthenticateClientApp` 与 `AuthenticateClientKey` **互不越界**
  （密钥型 `public_id` 为空 → 不能用应用标识认证；应用型 → 也不能用 Bearer 进来）。
- `relay.authenticate(token, appID)` 统一两路：**密钥优先，密钥无效时回落到应用标识**
  （很多 OpenAI 兼容客户端会强制发 `Authorization`，不能因此把合法的应用标识一起废掉）；
  密钥「已过期」直接回 `token_expired`，不回落。
- 管理端：`keyless` 创建；`keysList` 返回 `AuthMode`/`PublicID`；`connection` 返回
  `auth_mode`/`app_id`，并在 warnings 里点明「应用标识公开，能访问到网关的人都能调用」。
- 管理台：创建表单加「接入方式」；凭据列区分两种；接入信息弹窗按 auth_mode 切换
  凭据行 / 说明 / curl 示例 / 风险提示。demo 页面也改成应用型（`/__config` 里连 `token` 字段都没有）。

**测试当场抓到的真实缺陷**：应用型凭据创建时我把 token 清空**之后**才算摘要 → 所有应用型凭据
得到同一个「空串 HMAC」→ 第二条撞 `token_digest` 的 UNIQUE 约束。修法：**先算摘要，再丢弃明文**。
教训：「不返回某个值」和「用某个值做计算」必须分开写。

**实测**（真实实例 v0.3.6）：建应用型凭据返回的 `token` 与 `token_hint` 都是空串；
只带 `X-App-Id` 拉模型 200、对话 200（真实上游回「收到/成功」）、流式 85 帧含 `[DONE]`；
未知标识 401、无凭据 401、**拿应用标识当密钥用 401**、停用后 401、重新启用 200；
app 标识 + 无效密钥 → 200（回落生效）。

**回归**：`go test ./...` 全绿；`_e2e/run_client_onboarding.py` **48/48**（新增 9 项）；
`_e2e/run_e2e.py` 66/66。镜像 `civic-relay:v0.3.6` 已在本机实例运行。

**重复踩的坑**：一天内两次把中文放进 HTTP **头值**（`X-App-Id: app_不存在`、`Bearer crk_伪造的密钥`），
urllib 直接 `latin-1 codec can't encode`。**HTTP 头值只能是 latin-1**，探针脚本里别用中文。
