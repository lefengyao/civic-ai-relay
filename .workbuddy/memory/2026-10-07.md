# 2026-10-07

## 新增 CORS 支持（CORS_ALLOWED_ORIGINS）
- 老板指令「这个项目没有cors，加上」。
- 实现：`internal/httpapi/cors.go` 新增 `withCORS` 中间件，挂在 `server.go` 的最内层
  （withRequestLog → withAccessLog → withCORS → mux），覆盖公开接口、管理台与探针。
- 配置项 `CORS_ALLOWED_ORIGINS`（config.Settings.CORSAllowedOrigins）：
  - `*`（缺省/空值）= 全放行（与项目「出厂默认不限」哲学一致）；
  - `off` = 不下发任何 CORS 头；
  - 逗号分隔来源白名单 = 仅精确匹配（大小写不敏感）回显 Origin；
  - 白名单里混入 `*` 按全放行处理；来源必须是 `scheme://host[:port]`，不允许路径（validateOrigin）。
- 热生效：`NewServerWithAdmission` 签名新增 `settings func() config.Settings`（传 source.Get），
  管理台保存后 onSettingsChange → source.Set → 中间件逐请求读取，无需重启。
- 预检 OPTIONS：放行来源直接 204 短路，Access-Control-Allow-Headers 回显浏览器声明头；
  非放行来源交给下游（浏览器因缺 ACAO 自行拦截）。认证走请求头非 Cookie，无需 Allow-Credentials。
- 管理台 admin.html 的 cfgLabels 补了该字段的中英说明（配置页自动渲染 EnvMap，无需其他改动）。
- 测试：cors_test.go 六个用例（通配/预检/白名单/off/无 Origin/解析表）；全绿。
- 踩坑：测试里手写 base64 密钥样例两次失败——StdEncoding 必须带 padding，且 43 字符无填充非法；
  正确做法是在测试里用 `base64.StdEncoding.EncodeToString(make([]byte, 32))` 现生成。
- 未跑 _e2e（需构建镜像）；改动不涉及鉴权与额度逻辑，e2e 非必须，下次打包发布前跑一遍即可。
