## 只有跑起来才会发现的问题（都已修）

1. **周期额度静默失效**：`period_limit_start` 是秒级 RFC3339，账目行是 RFC3339Nano，
   SQL 文本比较下 `…48Z > …48.219Z` → 同秒账目被排除。全部窗口边界改 `julianday()`。
2. **播种细节**：未设的列要保 NULL（`COALESCE(col, NULLIF(?,0))`）；金额必须 `ParseFloat × 1e6`，
   `ParseInt` 会把 12.5 截成 12。
3. **`config.Store.Write` 会合并未知键** → 用它删键等于没删；新增 `WriteMapping`（不合并）。
4. **前端把 `TensionPct==0` 当「不限」** → 设完额度的组仍显示不限；改看 Token 三列本身。
5. **自定义周期要同时填天数和至少一项限额才生效**（`periodActive` 既有语义），界面原本没说。
6. 加列后「状态」被挤成两行 → 组名/状态/额度列加 nowrap 与最小宽度。

## SSH 爆破防护（12:20，老板授权后执行）

**背景数据**：今天到 12:15 失败 14,814 次、昨天整天 378,860 次；其中 14,200 次（96%）来自单机
`195.178.110.220`（TECHOFF SRV LIMITED，英国注册/国家码 AD，每分钟 399 次、多连接并发、
字典扫 root 与 thiennt/joydhan/moodle/dspace/deployer 等常见运维账号名）。**没有定向性，是全网撒网器**。
服务器 Ubuntu 22.04（日志在 `/var/log/auth.log`，不是 `/var/log/secure`）；原有防护：**只有 ufw，无 fail2ban/sshguard**。

- **ufw 封头号源**：`ufw insert 1 deny from <ip> comment '...'` → 规则 1，持久化在 `/etc/ufw/user.rules`。
- **fail2ban 0.11.2**（apt 源可达，仅 3 个包）：配置写 `/etc/fail2ban/jail.local`
  （bantime 3600 / findtime 600 / maxretry 5 / `bantime.increment=true` factor 2 maxtime 7d / backend auto）。
  `backend=auto` 在 rsyslog 有 auth.log 时走 pyinotify，正常。`systemctl enable --now fail2ban` 后
  自检日志 `File list: /var/log/auth.log`、`Currently banned: 5`（会回读历史失败记录，属正常）。
  `iptables -S INPUT` 第一条是 `-A INPUT -p tcp -m multiport --dports 22 -j f2b-sshd`，**排在 ufw 链之前**，所以封禁优先于 ufw 放行。
- **SSH 密钥**：本机 `ssh-keygen -t ed25519 -f ~/.ssh/civic_waigame_ed25519 -N ""`
  → 公钥（指纹 `SHA256:LdgFqp167oVl8vtRM6//exjUwVLMkea1lJCHML5aD+w`）写入 `/root/.ssh/authorized_keys`（600）
  → `sshd_config` 把 `PubkeyAuthentication no` 改 yes，`ssh_password` 保持 yes（老板选过渡）
  → `sshd -t` + `systemctl reload ssh`（**reload 不断开现有连接，别用 restart**）。
- **怎么验证公钥真的生效**（本机连不上 9045，只能用回环）：临时 `ssh-keygen` 生成测试密钥 →
  追加到 authorized_keys → `ssh -i /tmp/tk -o PasswordAuthentication=no root@127.0.0.1 "echo KEY_LOGIN_OK"`
  → 拿到 KEY_LOGIN_OK 说明公钥链路通 → **恢复 authorized_keys 到只有老板那把 + `shred -u` 删测试私钥**。
  这样既验证了机制，又不让任何真实私钥落盘到服务器。
- Windows 上 `chmod 600` 对私钥无效（NTFS 不看 unix 位），要 `icacls <path> /inheritance:r /grant:r "<user>:R"`。
- **待办**：① 老板用密钥连稳之后关 `PasswordAuthentication`（那才是根治）；② ufw 还开着 `8888`（宝塔面板）、
  `21`(FTP)、`39000-40000`、rustdesk 21115-21117——面板与 FTP 对全网开放的风险其实比 SSH 更高；
  ③ 老板出口 IP 是 `58.19.x`/`113.57.x` 且会变，**不能做 IP 白名单**，只能走密钥。
