## civic-relay 接入 trailblazer-deploy（部署管理器）

目标：像 storyfabric-web 一样，用部署管理器部署/更新 civic-relay。改动刻意保持最小。

### trailblazer-deploy 侧（D:\生产项目\项目\TrailblazerStation\trailblazer-deploy）
- **契约** `packages/contracts/src/site.ts`：`SitePackageContract` 增加可选
  `dockerfileName` / `useImageHealthcheck`；`SiteProfile` 增加可选
  `volumes: {source,target}[]` 与 `buildArgs: Record<string,string>`；新增 `SiteVolumeMount`。
  全部可选 → storyfabric 既有档案与测试零改动。
- **档案** `packages/core/src/services/siteProfile.ts`：新增 `CIVIC_RELAY_PROFILE` 内置档案
  （dockerfileName='Dockerfile.relay'、useImageHealthcheck=true、
  volumes 复用命名卷 civic-relay_civic-relay-config/-data、buildArgs RUNTIME_IMAGE=scratch、
  releaseCatalog=false）；validateSiteProfile 会**丢弃未知字段**，所以新可选字段必须显式校验透传。
- **部署器** `packages/core/src/services/siteDeployer.ts`：
  - `--file` 用 profile 的 dockerfileName；findArchiveContextRoot/validateBuildContext 同步参数化，
    present() 对目录名去尾部 `/` 再匹配（zip 不保证列目录条目）。
  - `useImageHealthcheck` → 不传 `--health-cmd` 系列参数（distroless/scratch 无 shell，
    wget/curl 探针永远失败会把健康安装回滚——这是接入 civic 的**硬前提**）。
  - install 挂 profile 卷；update 用 `mountedTargetsFrom(existing.runArguments)` 去重
    （inspect 回放的 --volume 与 profile 卷同 target 不能重复传）。
  - buildArgs 以结构化数组传 `--build-arg k=v`；结果文案改用 `siteLabel`（默认 StoryFabric-web，
    既有测试断言 'StoryFabric-web 安装成功' 不破坏）。
- **映射点** `staticSiteAdapter.ts` createFor 里把 profile 新字段传给 deployerFactory。
- 验证：`pnpm typecheck` 干净；vitest **374 passed**（新增 7 个用例）。
- pnpm 调用：全局 pnpm 的 sh shim 坏 → `node /c/Users/15610/AppData/Roaming/npm/node_modules/pnpm/bin/pnpm.cjs <cmd>`；
  vitest 从仓库根直接 `pnpm.cjs exec vitest run`（desktop 的 test 脚本里 `--dir ../..` 是从 apps/desktop 视角的）。
