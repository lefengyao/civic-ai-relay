## 修复：根路径 404

用户直接访问 http://127.0.0.1:8000/ 报 404（mux 没注册根处理器）。在 `internal/httpapi/server.go` 加根路径 302 重定向到 `/admin/`，`/favicon.ico` 返回 204（消除浏览器控制台 404 噪音）；未知路径仍 404。已重编译重启验证：`/`→302→200，`/favicon.ico`→204。

## 新增：客户端密钥标识 + 重置密钥

用户问"Key 列表只有名称没有密钥"。原因：密钥只存摘要（token_digest），明文仅创建时显示一次，不可还原。方案：
- 迁移 v4/v5：`client_keys.token_label`（非敏感随机标识 `key-xxxxxx`，与密钥无关），v5 回填老 Key
- 新接口 `POST /admin/api/keys/{id}/rotate`：重置密钥，新明文只返回一次，旧 token 立即失效
- UI：Key 表加"密钥标识"列 + "重置密钥"按钮；重置弹窗一次性显示新密钥；关闭弹窗即清空 DOM 中的明文
- **重要教训**：最初想在列表显示密钥前缀（crk_xxx），被项目自带的安全测试拦下——`admin_test.go` 断言列表绝不能含 `crk_`。这是项目刻意的安全不变量：任何密钥字符都不得出现在列表接口中。显示标识必须是无关的随机值。
- 断点文档：`docs/breakpoint-2026-09-10.md`

## 新增：密钥缩略显示在标识下方

用户要求在密钥标识下显示脱敏缩略。方案（不破坏列表不泄露密钥字符的安全不变量）：
- 迁移 v6：`client_keys.token_hint`（如 `crk_cHja…`，只保留前 8 字符 + …），Create/Rotate 时写入；只存摘要的老 Key 无 hint，显示"重置后显示"
- 专用接口 `GET /admin/api/keys/hints`（`keysHints` handler）返回缩略；列表接口本身不返回该字段，`admin_test.go` 的 `crk_` 断言依然通过
- 前端：`loadKeys` 后异步调 hints 接口填充 `.token-hint` 行；重置后同步刷新
- 实测：重置后 hint `crk_cHja…` 与新 token 前 8 位一致；列表仍无密钥字符；迁移 1-6 全应用。截图 ui-15/ui-16 已更新
