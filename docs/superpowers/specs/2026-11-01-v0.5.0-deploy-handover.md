## 四、部署步骤

严格按 `docs/deploy-prebuilt.md` 第 1~5 节；包已构建好，从第 2 节「上传」开始。要点：

### 1) 上传三个文件到 `/opt/civic-ai-relay/`

| 本机 `dist/deploy-v0.5.0/` | 服务器 |
|---|---|
| `civic-relay` | `civic-bin` |
| `src.tar.gz` | `src.tar.gz` |
| `DEPLOYED_COMMIT` | `DEPLOYED_COMMIT` |

> **二进制怎么传**：OpsHelper 的 SFTP 写文件只支持 UTF-8 文本，14MB 二进制不能靠它拼内容。
> 先 `ToolSearch` 查一下有没有「上传本地文件」类的工具（能直接给路径的那种）；没有就让老板用
> **宝塔文件管理器**或 WinSCP 拖三个文件上去（几十秒的事，比任何绕路都快）。
> 传完必须两端对 sha256：`sha256sum civic-bin src.tar.gz` 与 `SHA256SUMS` / `DEPLOYED_COMMIT` 比对。

### 2) 停机 + 一致备份（**不可跳过**）

```bash
cd /opt/civic-ai-relay && docker compose stop
TS=$(date +%Y%m%d-%H%M%S)
docker run --rm -v <data卷>:/d -v /opt/civic-ai-relay/backups:/out alpine:3.20 tar -czf /out/civic-data-$TS.tar.gz -C /d .
docker run --rm -v <config卷>:/c -v /opt/civic-ai-relay/backups:/out alpine:3.20 tar -czf /out/civic-config-$TS.tar.gz -C /c .
ls -lh /opt/civic-ai-relay/backups/
```

确认两个 tar.gz 都在再往下走。配置卷里含 `RELAY_ENCRYPTION_KEY`——丢了上游 Key 就解不开，
两份必须一起备份。本机也留一份副本到 `C:\Users\15610\civic-backups\`。

### 3) 解包 + 换二进制 + 建镜像

```bash
cd /opt/civic-ai-relay
tar -xzf src.tar.gz && rm -f src.tar.gz
docker build -f Dockerfile.prebuilt -t civic-relay:v0.5.0 .
cp -a .env ".env.bak-$(date +%Y%m%d-%H%M%S)"
sed -i 's/^CIVIC_RELAY_VERSION=.*/CIVIC_RELAY_VERSION=v0.5.0/' .env
sed -i 's/^CIVIC_RELAY_COMMIT=.*/CIVIC_RELAY_COMMIT=6dbd6d4/' .env
sed -i 's|^CIVIC_RELAY_BUILD_DATE=.*|CIVIC_RELAY_BUILD_DATE=2026-11-01T03:51:34Z|' .env
docker compose up -d          # 不加 --build；永远不要 down -v
```

### 4) 验证（比平时多两条，这次特有）

```bash
docker ps --filter name=civic --format '{{.Names}} | {{.Image}} | {{.Status}}'
curl -s http://127.0.0.1:8000/healthz    # 应为 v0.5.0 (commit 6dbd6d4...)
curl -s -o /dev/null -w 'readyz=%{http_code}\n' http://127.0.0.1:8000/readyz
curl -s -o /dev/null -w 'admin=%{http_code}\n' http://127.0.0.1:8000/admin/
docker logs --tail 40 civic-ai-relay-civic-relay-1
```

**本次必须多确认的一行日志**：

```
INFO 全局额度配置已灌入 N 个分组并从 relay.env 移除（旧 TOKEN_LIMIT_*…）
```

- 出现了 → 播种成功：旧全局额度已搬进每个分组、relay.env 已清理。
  接着打开管理台「模型组」，逐个看「额度」列**不再是「不限」**、组概览里限额数字与升级前一致。
- 没出现且 relay.env 里本来就没有额度键 → 也正常（说明生产早就没设）。
- 没出现但 relay.env 里**有** `TOKEN_LIMIT_*` → 有问题，停下来看日志。

另外抽一个 Key 实际调一次 `/v1/chat/completions`（额度已满时应返回 429，`error.detail`
里带「分组「X」#N」），确认判定链在新版本里真的按组工作。

## 五、回滚

```bash
cd /opt/civic-ai-relay
sed -i 's/^CIVIC_RELAY_VERSION=.*/CIVIC_RELAY_VERSION=v0.4.0/' .env
docker compose up -d
```

v18 是**纯加列**（`ALTER TABLE model_groups ADD COLUMN`），v0.4.0 的二进制不看这 10 列，
所以切回旧镜像能直接跑，不需要恢复备份。备份是兜底：只有在迁移写坏库时才用。
