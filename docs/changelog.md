## v0.5.0 — 额度从全局搬进每个分组

**当时存在的问题**

全局额度（`relay.env` 里的 `TOKEN_LIMIT_*` / `AMOUNT_LIMIT_*` / `PERIOD_LIMIT_*`）是**整个网关共用一份**。
但分组已经是「一个团队 / 一个软件一条通道」的单位，共用一份额度意味着：A 组把今日用量打满，
B 组的客户端全部 429；想让内部组宽松、外包组收紧，只能靠 Key 级总额度勉强凑，而 Key 额度是
**累计不轮换**的，对「每天 5 元」这种需求完全不对路。分组概览也一直按「走组内渠道的请求」统计，
与额度扣减的口径（按账目行归属）不是一回事，两边数字对不上时无从判断谁对。

**改了什么**

- 迁移 v18：`model_groups` 加 10 列（4 窗口 × Token/金额 + 周期长度 + 周期起点），全部可空，
  `NULL` 或 `0` = 不限。**升级不会让任何分组突然被限额**（不设就是不限）。
- 判定改为在预留事务内**从密钥所属分组那一行**读额度，改完下一次请求即生效；`QuotaLimits`
  保留原字段但语义从「全局配置快照」变成「本次请求生效的额度」，五个窗口判定函数逻辑一行未改。
- 启动播种：`relay.env` 里残留的全局额度会被灌进**每个现有分组**（只填还没设过的列），
  然后从文件里删键；删键本身就是幂等标记。日志 `全局额度配置已灌入 N 个分组并从 relay.env 移除`。
- 管理台：概览摘掉四张全局额度卡（全局视图已经没有限额可展示）；模型组列表加「额度」列
  （三个主窗口最紧张的那个占比，≥80% 黄、用满标红「已欠费」）；组编辑弹窗加 9 个额度输入框
  （`0 = 不限；留空 = 保持原值`，金额按元进出、库里存微元）；组概览弹窗用四张额度卡展示
  「已用 / 本组限额」，口径说明改为「仅计入归属本组的请求」；删组确认写明将解绑多少把密钥。
- 顺手补掉阶段 A 的两处欠账：密钥编辑弹窗里**当前分组即使停用也显示**（标「已停用」），
  且只在选中值真的变化时才 `PUT /group`（避免「只改名字却静默解绑」和停用组的 400）；
  首次启动日志区分「首启」与「恢复既有凭据」两种文案。

**踩过的坑**

| # | 坑 | 后果 / 修法 |
|---|---|---|
| 1 | 周期起点自动填的是**秒级** RFC3339（`…48Z`），账目行是 RFC3339Nano（`…48.219Z`）；SQL 里按**文本**比较，`48Z > 48.219Z` | 同一秒内写入的账目被整段排除在周期窗口外，**周期额度静默失效**（永远 0 用量、永不拒绝）。窗口边界全部改 `julianday()` 数值比较 |
| 2 | 播种时把「没设」写成 `0`、金额用 `ParseInt` 读 | 前者会让所有分组从 NULL 变 `0`（语义上仍是「不限」，但丢掉了「未设」），后者把 `12.5` 截成 `12`。改为 `COALESCE(col, NULLIF(?, 0))` + `ParseFloat × 1e6` |
| 3 | `config.Store.Write` 会把未知键**合并**回文件 | 用它在播种后删键等于没删（下次启动又灌一遍）。新增 `WriteMapping`（不合并）专用于此处 |
| 4 | 前端把 `TensionPct == 0` 一律渲染成「不限」 | `0` 有两种含义：没设限额 / 设了但一点没用。必须看 Token 三列本身，否则刚设完额度的组还显示「不限」，运维以为没生效 |
| 5 | 自定义周期**只填天数不填周期限额**不生效（既有语义，`periodActive` 要求至少一项周期限额） | 界面上原本没说，运维填完 3 天以为已生效。编辑弹窗里写明「要同时填周期长度与至少一项周期限额」 |

**BREAKING CHANGE**：`TOKEN_LIMIT_5H` / `TOKEN_LIMIT_DAILY` / `TOKEN_LIMIT_WEEKLY` /
`TOKEN_LIMIT_PERIOD` / `AMOUNT_LIMIT_5H` / `AMOUNT_LIMIT_DAILY` / `AMOUNT_LIMIT_WEEKLY` /
`AMOUNT_LIMIT_PERIOD` / `PERIOD_LIMIT_DAYS` / `PERIOD_LIMIT_START` 不再从 `relay.env` 读取。
`GET /admin/api/overview` 也不再返回 `five_hour` / `daily` / `weekly` / `period` 四个窗口
（改看 `GET /admin/api/groups/{id}/overview`）。旧部署升级后额度会自动搬进各分组，行为不变。

**已知但尚未实现**

- `_e2e/run_e2e.py` 的 39 项断言里「额度对照实验」依赖已删除的全局额度配置接口，本版本后**必然失效**。
  本机没装 Python 跑不了，也不做盲改——待装好 Python 后改为「按分组设额度 + 断言 429 带分组名」重跑。
- 金额展示仍有历史遗留的 `¥12.500000` 形态（`fmtYuan` 对非整元的 6 位小数尾部零只剥 3 个）。
  属全局金额格式，改动会波及请求日志与用量分析，留待单独处理。

## v0.3.7 — 修复「流式对话突然中断」（线上故障）

**当时存在的问题**

| # | 问题 | 后果 |
|---|---|---|
| 1 | 上游 HTTP 客户端设了 `http.Client.Timeout = connect+read+write`（默认 **340 秒**）。这是**整个请求的总超时，包含读取响应体的全部时间** | 任何超过 340 秒的流式回答被**无声掐断**。记录里只留 `upstream_status=200` + **零 token** 的 `failed`，从管理台完全看不出是超时 |
| 2 | `MAX_STREAM_DURATION`（默认 30 分钟，管理台可配）**从未作用到请求上**，只被后台回收循环当作「陈旧预留」的阈值 | 管理台显示 30 分钟、实际生效 340 秒，两个数字互相矛盾且无人能察觉 |
| 3 | `UPSTREAM_*_TIMEOUT` 改了需要**重启容器**才生效（启动时按值交给 Registry），但 `RestartOnlyChanges` 只列了 `HOST`/`PORT`/`DB_PATH` | 管理台显示「已即时生效」，运维据此以为调大了超时——排查时最容易走错的一步 |

**修复**

- 上游客户端**不设总超时**，职责拆开：「上游不响应」→ `UPSTREAM_READ_TIMEOUT`（`ResponseHeaderTimeout = connect + read`）；「流跑多久」→ `MAX_STREAM_DURATION`（relay 层用 context 施加，**0 = 不限**）；「客户端断开」→ 请求自身 context。
- `MAX_STREAM_DURATION` 现在真的生效，且**热生效**；cancel 绑到 `response.Body.Close()`（调用方本来就会 defer，不会漏 timer）；失败分支用原始 ctx 结算，避免 ctx 已超时导致落库失败。
- `UPSTREAM_CONNECT/READ/WRITE/POOL_TIMEOUT` 四项加入 `RestartOnlyChanges`，管理台会明确提示需重启。

**回归**：`internal/upstream/client_test.go`（白盒钉住 `Timeout==0` + 慢流必须读完）、
`internal/relay/service_test.go`（`MAX_STREAM_DURATION` 真的作用到 ctx、`0 = 不限`）、
`_e2e/run_stream_timeout_check.py`（6 秒慢流 + 3 秒聚合超时：旧版只收到 3 帧且无 `[DONE]`，新版完整读完并记 `completed`）。

## v0.3.6 — 应用型凭据（客户端里没有密钥）

**当时存在的问题**：客户端**必须持有 `crk_` 密钥**。而写进客户端里的任何秘密迟早会被提取 —— 用户能把密钥带去别的软件里用。

**修复**：`keyless: true` 创建**应用型凭据**，服务端生成公开的应用标识（`app_…`）并**丢弃密钥明文**（不返回、不落盘），客户端只用请求头 `X-App-Id` 接入。两套认证**互不越界**（密钥型的 `public_id` 为空，应用型无法用 Bearer），同给时密钥优先、失败回落应用标识。

> ⚠️ 边界：应用标识是**公开的**，能访问到网关的人都能调用 —— 真正的门是「谁能访问到网关」（内网/防火墙/反代），因此必须配并发与额度上限。跨不可信网络的正确做法是让客户端连**你自己的中转服务**。

**踩过的坑**：创建应用型凭据时先清空 token 再算摘要 → 所有记录得到同一个「空串 HMAC」→ 撞 `token_digest` 的 UNIQUE 约束。必须**先算摘要再丢弃明文**。

## v0.3.5 — 短时令牌（客户端凭据会自己过期）

**当时存在的问题**：客户端 Key **永久有效**，只有手动停用/删除/重置才失效。凭据泄露后除非有人发现并吊销，否则一直可用。

**修复**：`client_keys.expires_at_utc`（`NULL` = 永久，**历史 Key 不受影响**）。创建/编辑可设 `ttl_seconds`（**三态**：缺省 = 不动、`0` = 改永久、`>0` = 从现在起重新计时即续期）。过期返回 **401 `token_expired`**（与 `invalid_api_key` 分开，客户端才知道该换令牌而不是当服务故障重试）。管理台显示剩余寿命（不足 24 小时标黄、过期标红）。

> 「留空不改有效期」这条必须守住，否则「重命名」会变成静默的永久续期 —— 已由 `admin_test.go::TestAdminKeyTTLThreeStates` 钉住。

## v0.3.4 — 客户端接入信息

**当时存在的问题**：明文密钥只在创建/重置时返回一次，Base URL 与模型名又分散在配置页和模型页，运维要自己拼 —— 拼错的表现是客户端 400/404，从错误信息里看不出是「填错了」还是「服务坏了」。

**修复**：`GET /admin/api/keys/{id}/connection` 一次给出 Base URL（按访问管理台的方式推断）、派生地址、脱敏密钥标识、**可用模型清单**（与公共 `/v1/models` 共用同一份 SQL，不会漂移）、所属分组、`issues`/`warnings`/`ready`。管理台 Key 行有「接入信息」按钮。

## 已知但尚未实现

- **客户端指定分组**：现在分组由服务端按凭据绑定决定，客户端不能选。要做需加「请求头指定分组 + 校验在该凭据已绑定的范围内」。
- **客户端自助换令牌**：短时令牌到期需管理员续期。若要客户端自己换，需要一层「用旧令牌换新令牌」的接口，并限定「仅临近过期时可换一次」。
- **公共接口的 CORS**：当前不带 `Access-Control-*` 头（`OPTIONS` 返回 405），网页类客户端**不能跨源直连**，必须走同源反向代理。要支持需显式加 CORS，但那会让 relay 对任意网页开放（浏览器里密钥明文可见），只在完全可信环境才建议。
